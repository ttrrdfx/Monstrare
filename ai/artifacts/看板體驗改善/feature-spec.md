# 功能規格書

## Metadata

- 功能：藍圖心智圖與看板即時同步
- 負責人：待指定
- 狀態：人工已核准（2026-09-05）
- 風險等級：中

## 問題

現有「藍圖」只是 Epic → User Story → Task 的直向卡片清單，當層級或任務增多時，不容易一眼理解工作分解、完成狀態與節點間的關係。

另一方面，頁面只在初次載入時取得任務卡與 Epic 資料。當另一個瀏覽器頁籤、其他使用者或 AI agent 更新 `cards/*.json` 後，已開啟的頁面不會自動反映變更，使用者必須手動重新整理。

## 使用者

- 在本機使用治理看板規劃與追蹤工作的開發者、產品負責人與 AI agent 協作者。
- 同時開啟多個看板頁籤，或讓外部程式直接修改 JSON 的使用者。

## 目標

- 將藍圖呈現為由左到右的心智圖，以 Epic 為根節點、User Story 為第二層、Task 為葉節點，並以連線表達層級。
- 保留現有進度資訊，讓使用者可從節點看出完成數、總數與百分比。
- 當任務卡或 Epic 資料在 server 端變更時，已開啟的頁面可在數秒內自動同步，不需手動重新整理。
- 在自動同步遇到未儲存的本地操作時，不靜默覆寫使用者正在編輯的內容。

## 非目標

- 不把藍圖做成自由繪圖或可任意新增邊的通用心智圖編輯器。
- 第一版不儲存使用者自由拖曳後的節點座標。
- 不新增帳號、權限、雲端資料庫或跨網路的多人協作後端。
- 不取代現有 git 同步機制；即時更新僅反映當前本機 server 能讀到的檔案狀態。
- 不改變現有 Card JSON schema 與關卡規則。

## 使用者故事（User Stories）

| 故事 | 身為／我想要／以便 | 驗收標準 |
|---|---|---|
| US-1 心智圖瀏覽 | 身為專案協作者，我想用心智圖理解 Epic、User Story 與 Task 的層級，以便快速掌握範圍與進度。 | 三層節點與連線正確；完成度正確；無任務與未分類任務仍可見。 |
| US-2 心智圖導覽 | 身為使用者，我想縮放、平移、收合分支並點擊 Task，以便在大型藍圖中專注某個區域。 | 支援縮放、平移、回到全景、分支收合；點 Task 開啟原有詳情 modal；鍵盤可操作。 |
| US-3 任務卡即時同步 | 身為已開啟看板的使用者，當任務卡被另一頁籤、其他使用者或 AI agent 完成時，我想自動看到狀態與進度更新。 | 變更後 3 秒內看板、藍圖、WIP 計數與進度一起更新，不需 reload。 |
| US-4 斷線與編輯保護 | 身為正在編輯卡片的使用者，我想知道連線狀態並避免輸入被遠端更新覆寫。 | 斷線時自動重連並顯示狀態；modal 內有未儲存輸入時不重繪該 modal，待儲存或關閉後同步。 |

## 使用者旅程

```text
使用者開啟藍圖
→ 看到 Epic → User Story → Task 的心智圖與進度
→ 縮放／平移／收合到關心的分支
→ 點擊 Task 開啟既有詳情 modal
→ 另一頁籤或 agent 將任務設為 Done
→ server 偵測資料變更並通知頁面
→ 看板與心智圖在 3 秒內同步新狀態
```

## 功能需求

- WHEN 藍圖資料載入完成，THE SYSTEM SHALL 以 Epic → User Story → Task 三層節點與連線呈現階層。
- WHEN Epic 或 User Story 含有任務，THE SYSTEM SHALL 顯示 `done / total` 與完成百分比。
- WHEN 任務卡的 `userStory` 不屬於對應 Epic，THE SYSTEM SHALL 將它放在「（未分類任務）」節點。
- WHEN 使用者收合 Epic 或 User Story，THE SYSTEM SHALL 隱藏其後代節點與連線，但保留該節點的聚合進度。
- WHEN 使用者點擊 Task 節點，THE SYSTEM SHALL 開啟現有任務卡詳情 modal。
- WHEN 使用者縮放或平移藍圖，THE SYSTEM SHALL 提供可視的「回到全景」操作，且不讓畫面容易迷失。
- WHEN `cards/*.json` 或 `epics.json` 在 server 端改變，THE SYSTEM SHALL 通知所有已連線的頁面重新取得最新資料。
- WHEN server 通過現有 POST/PUT/DELETE API 寫入資料，THE SYSTEM SHALL 發出與外部檔案修改一致的變更通知。
- WHEN 多個檔案事件在短時間內發生，THE SYSTEM SHALL 合併重複通知，避免反覆載入與閃爍。
- WHEN 即時連線中斷，THE SYSTEM SHALL 自動重連，並在斷線期間顯示「同步中斷」狀態。
- WHEN 卡片詳情 modal 存在已修改但未儲存的輸入，THE SYSTEM SHALL 保留當前輸入，不因即時事件重繪而覆寫。
- WHEN 即時更新與拖曳儲存同時發生，THE SYSTEM SHALL 以 server 成功回應的卡片狀態為準；寫入失敗時重新載入 server 狀態。

## 畫面

| 畫面 | 狀態 | 備註 |
|---|---|---|
| 藍圖心智圖 | 預設、載入中、空狀態、錯誤、大型資料、分支收合、行動裝置版 | 需進入 UI mockup 關卡，以現有控制塔視覺為基礎。 |
| 看板主畫面 | 即時已連線、重新連線中、同步中斷、更新中 | 看板本身不改版，新增輕量連線狀態。 |
| 任務卡詳情 modal | 無編輯、編輯中、外部更新待套用 | 保護正在輸入的標題與內容。 |

## 資料與 API

- 輸入：現有 `GET /api/cards`、`GET /api/epics` 回應；`cards/*.json` 與 `epics.json` 的檔案變更。
- 輸出：建議新增同來源事件流（SSE）端點，事件只需表示 `cards` 或 `epics` 已變更；前端再以現有 GET API 取得單一真實狀態。
- 驗證：事件不收任意使用者 payload；現有 Card schema 驗證與依賴檢查保持不變。
- 錯誤：SSE 中斷由瀏覽器自動重連；GET 更新失敗時保留上一份可用資料並顯示錯誤，不清空畫面。
- 建議技術選擇：SSE + `fs.watch` + debounce。本功能是 server 單向通知瀏覽器，無需 WebSocket 的雙向協定，也可維持零外部 dependency。

## 安全性與隱私

- 身分驗證：保持現有僅 bind `127.0.0.1` 的本機模式，不新增帳號系統。
- 權限：同現況，server 進程可讀寫的檔案即為可操作範圍。
- 敏感資料：SSE 不推送完整卡片內容，只推送變更類型，降低非必要資料暴露。
- 濫用情境：針對頻繁檔案事件做 debounce；移除已斷線的 response listener，避免記憶體洩漏。

## 驗收標準

- 藍圖中每張現有任務卡都剛好出現一次，並連到正確的 User Story 與 Epic。
- 於 50 張 Task、10 個 User Story 的測試資料下，藍圖可透過縮放、平移與收合流暢瀏覽，無節點重疊到無法辨識文字。
- 變更卡片為 `done` 後 3 秒內，所有已開啟頁籤的欄位、進度、Task 外觀與 WIP 計數均正確更新。
- 直接修改或 git pull `cards/*.json` 與 `epics.json` 時也能觸發同步，不只支援透過 HTTP API 的變更。
- 關閉 server 後頁面顯示同步中斷；server 重啟後頁面自動恢復並取得最新資料。
- 在詳情 modal 輸入但尚未 blur 儲存時觸發外部更新，當前輸入不會消失。
- 新功能不改變現有 POST/PUT/DELETE API 輸入輸出、dependsOn 防呆與 JSON 格式。
- 不新增 production dependency，server 仍可以 Node.js 內建模組啟動。

## 驗證計畫

- 單元測試：階層資料轉換、進度聚合、未分類案例、檔案事件 debounce。
- 整合測試：修改單卡、bulk 更新、新增、刪除與直接檔案修改均觸發 SSE；斷線 client 會被移除。
- E2E：同時開啟兩個頁籤，在 A 完成卡片，驗證 B 不 reload 即更新；驗證編輯保護與斷線重連。
- 視覺：對藍圖預設、空、大型資料、收合、行動裝置、斷線狀態截圖比對。
- 手動：直接修改 JSON、git checkout/pull 檔案、多頁籤、server 重啟與長時間連線。

| 順序 | 功能卡 | 分軌 | 範圍 | 主要驗收 |

### 建議依賴順序

```text
卡 1 → 卡 2 → 卡 3
             卡 4 → 卡 5
卡 3 + 卡 5 → 卡 6
```

## 待人工核准的假設

- 心智圖第一版採「由左到右、自動佈局」，而非從中心放射或可自由拖曳定位。
- 即時的定義是「同一台電腦、同一個 Node server 下的多頁籤與外部檔案更新」，不是網際網路多人伺服器。
- 第一版同步策略是收到變更通知後重取完整 cards/epics，不先做單卡 patch 協定。
